Important security and correctness risks
-----------------------------------------

  config.xml and the log. The secret uses DPAPI LocalMachine. The initializer
  does not set restrictive ACLs.
- The main script reads up to 2000 characters of HTTP response body on failure

  response-body characters on failure. Do not run either live test until this

- Main script's finally nulls sensitive variables but does not zero byte arrays.
- The event ID uses a millisecond timestamp without a random component. A PRTG

- Status is hard-coded to Down for Alert and Up for Recovery.

Conversation/tooling lessons
----------------------------
- The first terminal was PC24-1061, not the PRTG server. Always confirm host,
  PowerShell version, and services before server diagnostics; user runs
  production commands directly on the server.
- In PowerShell 5.1, do not pipe directly after a foreach statement block.
  Assign the foreach output to a variable, then pipe that variable.
- config.xml is Export-Clixml-style serialized data, not simple named XML
  elements. Inspect property names and presence only; never print values.
- Do not catch Get-WinEvent errors into one generic "inaccessible" message.
  Preserve only safe error type/FullyQualifiedErrorId metadata, because no
  matches and access/query failures are different outcomes.
- Keep every server command read-only and scoped; never dump config, logs,
  event messages, response bodies, or raw security records.
